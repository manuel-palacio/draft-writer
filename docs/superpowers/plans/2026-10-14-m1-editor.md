# Draft Writer M1 (Editor) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A usable Draft Writer.app: open, edit and save plain Markdown with iA fonts, a centred text column,
inline Markdown styling, focus mode, typewriter scrolling and a stats footer.

**Architecture:** The pure text-analysis units live in a local Swift package, `DraftKit`, so they
build and test with `swift test` and need no app or Xcode UI. The SwiftUI `DocumentGroup` app target
depends on `DraftKit`, and all AppKit code stays in `DraftWriter/Editor/`. The Xcode project is generated
from `project.yml` by XcodeGen, so no hand-edited `.pbxproj` is committed.

**Tech Stack:** Swift 6, macOS 15, SwiftUI + AppKit (TextKit 2), swift-markdown, NaturalLanguage,
Swift Testing, XcodeGen, iA Writer fonts.

**Spec:** `docs/superpowers/specs/2026-10-14-draft-design.md` (sections "Platform and dependencies",
"Architecture", "M1 — Editor", "Testing", "Repository")

## Global Constraints

- Deployment target macOS 15.0; Swift language mode 6; bundle id `io.github.manuel-palacio.DraftWriter`.
- Dependencies: `swift-markdown` (github.com/swiftlang/swift-markdown, from 0.5.0). No other third-party code in M1.
- No hand-rolled Markdown parsing. All block and inline detection goes through swift-markdown.
- Styling, dimming and highlighting are TextKit 2 rendering attributes. They never change the characters,
  never add undo steps and never mark the document as edited.
- Saved files are UTF-8 plain text, byte-for-byte what the user typed.
- Fonts: iA Writer Duo (default), Mono, Quattro from github.com/iaolo/iA-Fonts, with their `LICENSE.md`.
  Default size 17 pt (range 12–28), line height 1.5, column width 70 characters by default.
- Reading time 238 wpm. Focus dimming ~30% opacity. Styling debounce 150 ms; stats debounce 300 ms.
- Shortcuts: ⌘D focus mode cycle (off → sentence → paragraph), ⌥⌘T typewriter scrolling.
- Every `NSRange` handed to AppKit is UTF-16 based.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Non-ASCII text (åäö, emoji, CJK).** swift-markdown source locations are line plus UTF-8 column,
   while AppKit uses UTF-16 offsets. Styled ranges must land on the right characters. Test pinned in
   Task 4 (`stylesAfterEmojiAndSwedish`).
2. **Typing with an input method (marked text, e.g. dead keys or Japanese).** Re-styling during
   composition must not break the composition. Pinned in Task 6 (coordinator skips styling while
   `hasMarkedText()`; manual check step).
3. **Empty document and cursor at the very end.** Focus and stats must not crash and must return
   sensible values. Pinned in Task 3 (`focusInEmptyText`, `focusAtEndOfText`) and Task 2 (`emptyText`).
4. **Windows line endings (CRLF) and Latin-1 files.** These must open, display and save back without
   corruption. Pinned in Task 1 (`decodesLatin1Fallback`, `preservesCRLF`).
5. **Large documents (50,000 words).** Typing must not stall. Pinned in Task 8 (performance test).

### Task 4: MarkdownStyler

**Files:** Create `Sources/DraftKit/SourceRangeConverter.swift`, `Sources/DraftKit/MarkdownStyler.swift`,
`Tests/DraftKitTests/MarkdownStylerTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public enum MarkdownStyle: Hashable, Sendable {
      case heading(level: Int), emphasis, strong, inlineCode, codeBlock,
           link, linkDestination, blockQuote, listMarker, syntaxMarker
  }
  public struct StyledRange: Hashable, Sendable { public let range: NSRange; public let style: MarkdownStyle }
  public enum MarkdownStyler { public static func styles(for text: String) -> [StyledRange] }
  struct SourceRangeConverter { init(_ text: String); func nsRange(_ r: SourceRange) -> NSRange? }
  ```
  `syntaxMarker` covers `#`, `*`, `_`, `` ` ``, ```` ``` ````, `>`, and the `[`, `]`, `(`, `)` of links.

- [ ] **Step 1: Write the failing tests.** Assert on `(substring, style)` pairs taken from the result:
  - `heading`: `"## Title"` → `("## Title", .heading(level: 2))`, `("##", .syntaxMarker)`.
  - `emphasisAndStrong`: `"a *b* **c**"` → `("*b*", .emphasis)`, `("**c**", .strong)`, markers `"*"` ×2 and `"**"` ×2 as `.syntaxMarker`.
  - `inlineCode`: `` "x `y` z" `` → `` ("`y`", .inlineCode) ``.
  - `fencedCode`: `"```\nlet a = 1\n```"` → the whole block `.codeBlock`, and no `.emphasis` inside even when it contains `*a*`.
  - `link`: `"[Draft](https://x.io)"` → `("[Draft](https://x.io)", .link)`, `("https://x.io", .linkDestination)`.
  - `listAndQuote`: `"- item\n> quote"` → `("-", .listMarker)`, `("> quote", .blockQuote)`.
  - `stylesAfterEmojiAndSwedish`: `"👋 åäö *ord*"` → `("*ord*", .emphasis)` (checks the UTF-8 to UTF-16 conversion).
  - `emptyText`: `""` → `[]`.
  - `crlf`: `"# A\r\n*b*"` → `("*b*", .emphasis)`.
- [ ] **Step 2: Run.** Expected: FAIL.
- [ ] **Step 3: Implement `SourceRangeConverter`.** Precompute the UTF-8 offset of each line start (handle
  `\n`, `\r\n` and `\r`). Map (line, UTF-8 column), which are 1-based, to a `String.Index` through
  `text.utf8`, then to UTF-16 with `NSRange(_:in:)`.
- [ ] **Step 4: Implement `MarkdownStyler`** as a `MarkupWalker` over `Document(parsing:)`. Emit the node
  range for each block or inline. Derive marker ranges from the node range minus its content range (for
  example, a heading's marker is the leading run of `#`). Skip children of `CodeBlock` and `InlineCode`.
- [ ] **Step 5: Run.** Expected: PASS.

### Task 6: Editor view with styling

**Files:** Create `DraftWriter/Editor/EditorView.swift`, `DraftWriter/Editor/DraftTextView.swift`, `DraftWriter/Editor/AttributeApplier.swift`;
modify `DraftWriter/UI/DocumentWindow.swift` and `DraftWriterApp.swift` (replace the `TextEditor` placeholder).

**Interfaces:**
- Consumes: `MarkdownStyler.styles(for:)`, `Theme`, `Settings`.
- Produces:
  ```swift
  struct EditorView: NSViewRepresentable { @Binding var text: String; @Binding var selection: NSRange; let settings: Settings }
  final class DraftTextView: NSTextView   // TextKit 2 (init(usingTextLayoutManager: true))
  enum AttributeApplier {
      static func applyStyles(_ styles: [StyledRange], to tlm: NSTextLayoutManager, in range: NSRange, theme font: EditorFont, size: CGFloat)
      static func applyFocus(bright: NSRange?, to tlm: NSTextLayoutManager, fullLength: Int)
  }
  ```

- [ ] **Step 1: `DraftTextView`.** Set TextKit 2, rich text off, allow undo, spell check on and smart quotes
  off (it's Markdown). Set the base font and paragraph style (line height multiple 1.5). In `layout()`,
  set `textContainerInset.width` from `Theme.columnInset`.
- [ ] **Step 2: `EditorView` coordinator.** `textDidChange` pushes the text to the binding (the document
  handles undo). `updateNSView` replaces the text only when the binding differs from the view's string,
  so the coordinator never resets it while the user types.
- [ ] **Step 3: Styling.** After each change, re-style immediately the paragraph range around the edit
  (expanded by one paragraph each side), then schedule a full `MarkdownStyler.styles` pass 150 ms later.
  Skip both while `hasMarkedText()` is true and run them once composition ends. Apply the results with
  `NSTextLayoutManager.setRenderingAttributes(_:for:)`. Rendering attributes can't change the font, so
  heading size and bold/italic go through `NSTextContentStorage` display attributes in a
  `textContentStorage(_:textParagraphWith:)` delegate. That paragraph delegate is the only place fonts
  change; colours go through rendering attributes.
- [ ] **Step 4: Verify manually.** Build and run. Type `# Hello *world*` and check that the heading is bold
  and larger with the marker greyed. Undo removes the typed characters only, with no style-only undo
  steps. A fresh document does not show the edited dot until you type. Type `ä` with the ¨ dead key
  (option-u then a): the composition works.
- [ ] **Step 5: Commit.** `git commit -m "feat: NSTextView editor with inline Markdown styling"`

### Task 7: Focus mode, typewriter scrolling and stats footer

**Files:** Create `DraftWriter/App/Commands.swift`, `DraftWriter/UI/StatsFooter.swift`; modify `EditorView.swift`,
`DraftTextView.swift`, `DocumentWindow.swift`.

**Interfaces:**
- Consumes: `FocusController.brightRange`, `FocusMode.next`, `TextStats.compute`, `AttributeApplier.applyFocus`.
- Produces: View menu items "Focus Mode" (⌘D, title shows the current mode) and "Typewriter Scrolling"
  (⌥⌘T, checkmark).

- [ ] **Step 1: Focus.** On selection or text change, compute `brightRange` and call `applyFocus`, which
  sets `Theme.dimmed` foreground on the text outside the bright range. Limit it to the viewport range
  from `NSTextViewportLayoutController` plus one screen of margin, and refresh on scroll.
- [ ] **Step 2: Typewriter.** When on, set the vertical `textContainerInset` to half the visible height.
  After each edit or selection change, scroll so the caret's line fragment is centred (no animation
  while typing).
- [ ] **Step 3: Commands.** Use `FocusedValue` to reach the active window's settings, or the global
  `Settings` (focus and typewriter are app-wide in M1).
- [ ] **Step 4: Stats footer.** Recompute `TextStats` 300 ms after the last change in a `Task.detached`,
  using the selection's substring when the selection is non-empty. The footer shows
  `"1,234 words · 7,890 characters · 6 min"` and fades to 0 opacity while typing, then reappears on
  mouse move. The toolbar hides by the same rule (`.toolbarVisibility` with a hover state).
- [ ] **Step 5: Fallback banner.** If `openedWithFallbackEncoding`, show a dismissible banner at the
  top: "Opened as Latin-1. Draft Writer will save this file as UTF-8."
- [ ] **Step 6: Verify manually.** ⌘D cycles and dims sentence, then paragraph, then off. ⌥⌘T keeps the
  caret line centred while typing at the bottom of a long document. The footer counts match `TextStats`
